NAC3 live demos at yujin.app/nac-spec/

Spec version: 2.5.0-alpha.5 (v2.5 line complete; promoted to npm dist-tag latest).

NAC3 = Native Agent Contract. The spec that lets web UIs be driven by AI assistants, voice runners, RPA bots, and accessibility tools without per-app glue code.

The repo ships two families of runnable demos:

  1. Vanilla PHP examples at the repo root (example*.php) -- one self-contained page per spec milestone, loading the reference runtime directly.
  2. Framework + RFC demos under demos/ -- React/Angular study cases plus a focused walkthrough per shipped v2.4 / v2.5 RFC.

Side-by-side comparison: brownfield migration

Open example.php and example-v20-full.php in two tabs.

What is identical

  • HTML markup (every <article data-nac-plugin="X">, every data-nac-id, every i18n catalog reference, every handler)
  • Visual appearance (same layout, same widgets, same interactions)
  • Reference runtime (js/nac.js) loaded the same way
  • Existing data-i18n-key catalog references

What is different in the v2.0-full version

  1. Header docstring explaining it is a brownfield migration.
  2. One additional script tag: js/nac-v2-extensions.js loaded after nac.js and before example.js.
  3. One additional setup block (~80 lines) that builds a scope tree from existing data-nac-plugin attributes, enables HMAC sign via NAC.set_provenance_secret(), sets a tenant prefix, starts NAC.captureEphemeral(), and calls NAC.autoRegister.watch() on the cards container.
  4. One additional UI panel (#v20-panel) exposing live describe_v2(), validate_global_v2(), HMAC sign, and the isTrusted distinction.

That is the entire delta. Real adopters reuse this pattern verbatim.
